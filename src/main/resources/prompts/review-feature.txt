## Readiness criteria for Features

1. **Goal clarity** — The Feature has a clear, user-facing or system outcome.
2. **User perspective** — The beneficiary (user role or system) and the value they receive is stated.
3. **Acceptance criteria** — Specific, testable conditions for "done" are present.
4. **Technical scope** — Key technical decisions, integrations, or constraints are noted or inferable.
5. **Dependencies** — Upstream blockers or downstream requirements are identified.

readiness_score = round( (goal_clarity + user_perspective + acceptance_criteria + technical_scope + dependencies) / 5 )

## Complexity scoring rubric for Features (complexity_score 0–100)

- **0–20** Single user flow, no external integrations, simple UI or logic changes.
- **21–40** One or two user flows, minor backend changes, known integrations.
- **41–60** Multiple user flows, moderate backend changes, at least one external integration.
- **61–80** Complex user flows, significant backend work, multiple integrations, non-trivial data model changes.
- **81–100** Large number of user flows, cross-cutting concerns, deep technical risk, architecture changes.

Note: complexity_score is independent of readiness_score.
