## Test Writing Rules
- Place each test file in the correct test directory mirroring the source structure.
- Use the SAME test framework and assertion library already used in the project.
- For each unit under test, cover:
  - Happy path (typical valid inputs)
  - Edge cases (null/undefined inputs, empty collections, boundary values)
  - Error paths (exceptions, invalid state, rejected promises)
- Use the naming conventions already present in the project.
- Mock all external dependencies (repositories, services, HTTP clients, databases).
- Do NOT add disabled/skipped tests or tests that always pass trivially.
- If a test file already exists for a class, ADD missing test cases rather than replacing the file.
- If the coverage baseline lists packages/namespaces with 0% coverage, treat those as the highest priority — they have no tests at all.
